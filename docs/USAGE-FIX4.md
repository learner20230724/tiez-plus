# 使用体验与后台连接修正

日期：2026-09-25。Windows 0.1.0 / fix4；Android 0.1.2 / versionCode 3。

## 电脑端

- 状态放到 TieZ 标题右侧，显示紧凑的“Plus 已连接 / 未就绪”，不再单独占一行；点击看详情和连接码。
- 标题文字、标题栏空白及内边距显式调用 Tauri 窗口拖动。按钮、图标按钮、搜索框和连接码面板不触发拖动；不再假设 CSS 拖动样式或父元素属性会覆盖全部子元素。
- 关闭按钮说明“隐藏到托盘（继续接收手机推送）”。关闭窗口不退出进程，只有显式托盘退出等有退出码的请求才退出。
- Win+V 回显只随其持久化值变化初始化，不因不相关回调改变而重复使用旧快照覆盖开关。已属于本程序的快捷键检测不会再误判冲突或注销自身。启动时已启用的 Win+V 优先于可能残留的旧快捷键；主快捷键注册失败不再被吞掉。
- MQTT 网络轮询与串行请求处理分开，数据库/剪贴板慢处理期间仍处理心跳和网络确认。请求队列有界，过载明确要求手动重试；会话结束丢弃未处理队列，绝不跨断线自动补发。
- 日志只增加连接事件、请求类型、结果类别和耗时，不记录正文、令牌、密码。

## 手机端

- 只有推送页下拉刷新才读取系统剪贴板、持久化原文并选中。
- 打开应用、恢复前台、切换页面、快捷入口不读取剪贴板。冷启动恢复草稿，但不自动全选。已有文字不删除。
- 半开连接的应用层 ping 超时后关闭旧连接，让自动发现重新建立连接；不会保持“connected”而永久卡在坏连接上，也不会自动补发正文。
- 连接尝试具有代次校验，过期的连接完成不能覆盖新的前台会话。历史状态查询不再长期占用连接恢复锁。
- APK 包名、签名不变，可覆盖 0.1.1 升级，不要先卸载或清除应用数据。

## 已完成验证

- Node 54 / 54；手机 TypeScript 检查通过；桌面 TypeScript / Vite 生产构建通过。
- Rust 6 / 6：原有持久化去重与回执测试，加真实私有 Aedes 联调。模拟一次 8.5 秒处理和 49 条连续请求，5 秒 MQTT keepalive 仍可推进；文字全文保持一致，过载返回明确失败，无静默丢失。使用临时数据、独立随机端口、模拟文字处理，不调用系统剪贴板。
- 真实 AppHeader 浏览器 fixture：352 px 与 250 px 宽度检查；标题及有效内边距调用拖动，按钮/搜索框不调用，连接面板可打开关闭。浏览器 fixture 只验证原生拖动 API 的调用，不冒充 Windows 实际窗口位移测试。
- Android release 构建、签名验证通过；ABI 仅 arm64-v8a，包名不变，版本 0.1.2 / 3。签名证书 SHA-256 与 0.1.1 一致。
- 本轮排查时已安装 fix3 进程与 Broker 均在运行，应用层 ping 能应答；只读检查显示 Win+V 偏好仍已保存。未找到这次所述自动退出的确切崩溃证据，不能把所有后台失联都断言成同一个故障。

## 仍需实际使用确认

“几轮后必须把电脑窗口呼到最前面才能推送”尚未完整复现。本次修复了已发现的窗口/设置问题、半开连接恢复缺口和网络处理耦合，并增加定位日志；不宣称已经完成长时间休眠、断网恢复、Windows 真剪贴板及手机实机全部验收。

持续健康检查（仅 ping，不发送正文、不读历史或剪贴板）：

```powershell
node scripts/probe-desktop.cjs 7 10000
```

该脚本每次运行新增一个诊断设备身份，7 次探测共用一条连接，凭据仅在内存中。不应当作常驻监控频繁重新运行。
