# 多电脑推送与单电脑拉取

本次只更新源码，没有构建、安装或发布 APK。旧安装包不含本次改动；之后在 Windows 拉取最新源码再打包。

## 手机操作

- **推送**：所选内容发送到同一可信局域网内所有已发现的 TIEZ Plus 电脑，不受“电脑连接”中拉取来源的选择限制。只支持运行 Plus 的电脑，不是局域网里的任意设备。尚未发现的电脑需等待自动发现，必要时在设置中扫码发现。
- **拉取**：只向“设置 → 电脑连接”选中的电脑请求当前剪贴板和最近记录。该电脑离线时不自动改读另一台电脑；显示的缓存也按电脑隔离。切换电脑后，上一台电脑尚未返回的拉取结果不会显示或复制。
- **历史**：每条内容、每台电脑各有一条送达记录，显示电脑名和独立结果。部分失败会显示已确认条数与总条数，不会显示为全部成功。
- **重试**：未确认或失败记录从历史加入待推送后，只重试原电脑，复用原消息 ID；不重复发送给其它已成功的电脑。已成功记录主动重新加入，或编辑历史内容后再推送，作为新内容发送给当前发现的所有电脑。
- **离线与重连**：没有发现电脑时，新内容保留为草稿。断线或切到后台不会自动补发；恢复连接只探测和查询送达状态。已提交的发送可能已经送达，结果以回执/历史为准。

## 实现与兼容性

手机维护每台电脑独立的 MQTT 连接和注册凭据，设置中的连接只指定拉取来源。一次推送固定目标快照：45 秒内发现的电脑或仍保持连接的电脑。已发现地址每 15 秒复查，原生 UDP/mDNS 继续发现新电脑。

先用一个 SQLite 事务保存所有收件电脑的完整正文与独立消息 ID，再清空本次未被继续编辑的输入。事务中任何一个目标保存失败，整批回滚。电脑间最多并发 4 路，每台电脑内按所选内容顺序发送。单台失败不取消其它目标。

`plus_outbox` 自动增加 `target_name` 列；旧数据库、旧记录和正文保持兼容。拉取缓存使用 `instanceId + desktopId` 分区；旧的全局缓存不再展示，重新拉取即可。没有改动桌面协议或 Windows 构建脚本，不需要电脑同时升级才能使用手机广播。

## 验证与待验收

代码检查：`npm run check:mobile` 通过；`npm test` 共 67 项，59 项通过、8 项 Windows 专属测试在 macOS 跳过。`npm run check:isolation` 未通过：它校验仓库外的旧版源码目录，当前 Mac 没有这些独立原始目录，且清单使用 Windows 路径分隔符；不能据此判断旧版源码内容被修改。该检查仍需在保留原始源码目录的 Windows 环境执行。

新增测试覆盖真实 SQLite 的多目标原子写入、回执独立性、部分失败重试、内容顺序、连接复用、停止后的晚到连接，以及切换拉取来源时丢弃旧响应。生产手机 runtime 测试使用两个真实本机 MQTT broker，仅替换 Android 系统绑定，验证双机推送、选择来源拉取、部分失败和前后台取消。

尚未进行 Android 真机、多台物理电脑或 Windows 构建验收。Windows 打包后建议用两台电脑 A/B 验收：选择 A，推送后两台均收到；拉取只出现 A 的内容；改选 B 后只出现 B 的内容；关闭 B 后再次推送，在历史检查 A 成功、B 未确认，重试 B 时 A 不应重复接收。若 B 已超过发现有效期并断开连接，则它不属于新推送的目标快照。

Windows 仍使用仓库已有的 `npm run build:android` 流程。继续使用此前 Windows 工作目录中的 `.secrets` 签名文件，以便覆盖升级；签名文件不在 Git 中。本次没有执行该构建命令，也没有更改发布版本号。
